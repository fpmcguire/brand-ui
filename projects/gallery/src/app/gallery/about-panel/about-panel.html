About brand-ui

A reference spike, not production

brand-ui is a reference spike, not production software. It exists to model how a digital agency serves several unrelated clients from one shared component base, with each brand's identity applied through design tokens.

It has two purposes: domain learning, and workflow evidence, a small data point on how a role-separated workflow governs a reusable UI system. It makes no production, client-delivery, official-rebrand or rollout claim.

Three brands, four scopes

The gallery shows three brands across four scopes: CodeCraft Academy Light and Dark are two styling modes of one brand.

  • ArtAnon Shop: a real business owned by a third party. This is an unofficial concept exploration of turning its existing identity into tokens. It is not an official rebrand, and no affiliation or delivery claim is made. Only palette values and a text wordmark are used: no logo, artwork or photography.
  • IT English Mentor: a new brand for the Moderator's own freelance venture. Its visual direction may later become real.
  • CodeCraft Academy: a placeholder name for open-source tech and code examples.

The ui library

The Card in the ui library is built with Atomic Design, a way of organizing an interface from small parts into larger compositions. Small parts called atoms combine into molecules, and atoms and molecules combine into an organism, a distinct section of an interface that owns its behavior.

Here, Tag, SkeletonBlock and CodeWell are atoms. MediaArea and LoadingSkeleton are molecules. Card is the organism that composes them. These parts come from the separately built and installed @brand-ui/atomic package, which is built and packed locally and is not published, and ui re-exports that same Card, so there is one Card, not two separate implementations. The Card structure view in each scope shows the atoms, molecules and organism.

The ui public entry point exports four components: Button, TextInput, Card and Navigation. Button, TextInput and Navigation are established ui components and were not moved. It also has ThemeService, which owns the selected theme, and ThemeScopeDirective, which attaches a theme to one part of a page.

Every brand fills the same set of semantic token names (--bui-*), and the components hold no brand values. Switching brand changes tokens only, never component structure.

How the gallery relates to the library

The gallery is a separate review application. It imports the library only through the ui public entry point, as an outside consumer would, and the library does not depend on the gallery.

Everything the gallery adds is its own and is not library API: the brand scope switcher, the persistent hover, focus and active specimens, the token read-outs, the contrast evidence and the Design IDs.

Using the gallery

  • Brand scope switcher: choose ArtAnon Shop, IT English Mentor, CodeCraft Academy Light or CodeCraft Academy Dark, or All brands to stack the four scopes. Switching restyles every component without a reload.
  • Design IDs checkbox: shows or hides each Design ID beside token groups and component states.
  • Panel sections: each scope shows its tokens read from the computed style, then Button, Text input, Card, Navigation bar, Long label, Contrast evidence and Card structure.
  • About: this panel opens by itself on a browser's first visit. The About button in the top bar opens it again.

How this was built

Built with MOD-W v5.0.1, a role-separated workflow in which a Moderator (human-in-the-loop) approves each step and plan and a Tech Lead reviews each step before QA. Implementation was done by Claude Code acting as the Development Team.

The governing documents are in mod-w/; the methodology is at github.com/fpmcguire/mod-w.
